# Operations tools

Run from the repository root with Node 24 and authenticated Wrangler. No browser automation is used. `backup.mjs <new-archive> <key-file>` exports production D1 and every referenced published post, avatar, and event-cover variant, records checksums, and streams an AES-256-GCM encrypted archive. Full covers and thumbnails of published events remain required after the event ends or is cancelled; pending/deleted event objects are excluded. Shared object keys are copied once. Generate a 32-byte random key outside the repository and protect it with mode 600. A missing object or provider error fails the backup rather than producing a success claim. Plaintext intermediate files are private and removed on exit. Backup creation is read-only against production.

`restore-check.mjs <archive> <key-file>` authenticates/decrypts, checks SQL integrity and foreign keys, verifies each required photo checksum, and exercises quarantine by clearing sessions/tokens, invitation join credentials and retry payloads, push subscriptions and queued deliveries, and disabling active memberships. Older schemas without additional photo sizes, events, or invitation credential columns remain supported. It uses temporary local storage, removes it afterward, and cannot write to production. The synthetic CI exercise runs the exporter with a fake Cloudflare CLI, verifies all media variants, and rejects missing/corrupt event covers or thumbnails and tampered ciphertext. This verifies recoverability of the snapshot, not application serving from a restored Cloudflare environment.

The October 18, 2026 fix adds event covers to both export and restore requirements. Earlier archives containing published event rows may omit their media; the corrected checker rejects those incomplete archives. Take and verify a fresh backup with the corrected tool. Existing archives are not repaired by updating the checker.

`usage.mjs` reads Cloudflare's aggregate Worker, D1, and R2 metrics for the preceding day. It refreshes Wrangler OAuth through a read-only command, or uses `CLOUDFLARE_API_TOKEN`. Tokens and user content are never printed. `SLOWMASS_WRANGLER_AUTH_FILE` overrides the platform-default credential file location. No paid monitoring service, polling worker, public admin endpoint, or scheduled local job is provisioned.

See [operations](../../docs/operations.md) for retention, recovery sequencing, and cost thresholds. The nightly [Backup workflow](../../.github/workflows/backup.yml) runs `backup.mjs` and `restore-check.mjs` and uploads verified archives to S3; the scripts themselves never upload or schedule anything.

`check-deploy-migrations.mjs <query-json>` validates Wrangler's JSON response from `SELECT name FROM d1_migrations ORDER BY name` against checked-in SQL filenames and the complete deployment policy. With `--allow-automatic`, it accepts only pending migrations classified as automatic; without the flag, it requires all migrations to be applied. Unknown production history, malformed provider output, invalid/missing policy and pending manual migrations stop deployment. The workflow runs preflight, records a D1 recovery bookmark, applies migrations, then runs the strict postflight before publishing. Unit tests cover policy/history gates; a disposable local Wrangler/D1 test verifies old-client compatibility, failed-migration rollback, partial success and retry without duplicate application. No production data is used in tests.

`verify-deployment.mjs` compares production assets with `dist`, checks sign-in availability, signed-out private-resource boundaries, and event-preview rejection with synthetic invalid credentials using direct HTTP, and retries a bounded number of times for propagation. It uses no accounts or private data and performs no browser testing. A final failure requires operator investigation; it never automatically rolls back. Run only after deploying the matching build, outside the isolated test gate.

`push-keys.mjs <new-private-file>` generates a P-256 VAPID keypair through Node crypto and writes a mode-600 JSON file suitable for Wrangler secret bulk upload. It refuses to overwrite an existing file. Keep and back up this file outside the repository; reusing keys preserves browser subscriptions.

Restore quarantine also deletes shared-invite and event-link claims, permanently revokes shared links while clearing their encrypted bearer copies, and gives every event an unusable link version without ciphertext, so re-enabling a restored member cannot revive old links or access from merely opening one. Event links cannot be replaced, so quarantined events stop inviting new people; their hosts and everyone who answered keep access, and hosts create a new event to invite more people. Older snapshots without these tables remain supported.

Deployment verification includes all generated chunks under `dist/assets`, asserts their immutable caching policy, and checks that the HTML entry and startup recovery script still revalidate. This catches missing deferred screens before declaring deployment verification successful.

`npm run auth:audit` checks local email-alias and provider-identity collisions; append `-- --remote` for a read-only production audit. It outputs aggregate counts only, fails on collisions, and never merges or modifies accounts. Run it immediately before manual migration 0036 under the setup/runbook procedure. The SQL lives beside the command for inspection.
