# Startup diagnostics

A small write-only diagnostic sink helps investigate startup failures after the event without enabling provider request logs. The existing same-origin mutation guard applies; authentication is deliberately unnecessary because startup may fail before authentication completes. Browser reports are untrusted evidence, never an authorization input. A 2 KiB body limit, strict field allowlist, bounded numbers, UUID validation, and at most two failure entries exclude arbitrary text. Duplicate browser reports are ignored.

Only failed browser startups (including recovery on the second attempt), server bootstrap errors, and bootstrap requests still running after five seconds create records. The server retains separate stalled and completed snapshots with coarse auth/profile phases, timeout state, timings and database counters. Normal successful startup makes no diagnostic writes. No cookies, identity, IP address, raw URL, user agent, error text, response body or content is retained. Random startup and request IDs correlate attempts without a persistent device identifier.

Storage uses the existing D1 database, capped atomically at 200 records total. At capacity new records are dropped, including legitimate ones; the public endpoint can be abused to fill this small cap. This is diagnostic sampling, not an audit trail or rate limiter. Fifteen-minute maintenance deletes records older than 24 hours; a failed maintenance run can delay physical deletion, but cannot grow storage beyond the cap. Operator queries must filter the 24-hour window.

Browser reporting is best effort with a two-second abort, no cookies or retries, and no UI dependency. Server writes use waitUntil and swallow storage failures. A total network or D1 outage may therefore leave no record. Migrate before deploying; no migrations run during requests. Retention adds at most two server inserts per abnormal bootstrap and one browser insert per failed logical startup, plus bounded cleanup. Pending query counts and coarse phases provide clues, not proof of provider root cause.
