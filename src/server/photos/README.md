# Photo processing

Accepts at most 8 MiB of still JPEG, PNG, or WebP bytes and at most 40 megapixels. PNG and WebP container framing is checked for animation before decoding; GIF, SVG, HEIC, and unsupported containers are rejected. Cloudflare Images remains the trusted pixel decoder. A container check alone never makes an original safe to serve.

Output is a bounded WebP image with metadata removed, orientation applied, and aspect ratio preserved. Processing failures never return original bytes. The caller must authenticate, bound the upload stream, reserve quota before processing, and persist only successful output behind authorization. Feature modules own publication and durable image storage.

Upload transport bounds actual streamed bytes before decoding. Processing-attempt reservations are atomic and actor-scoped. The public reservation statement lets the post feature compose quota reservation and draft creation in one D1 transaction; retries cannot bypass limits. The monthly budget counts reserved transformation units: two per new post or avatar, one per legacy-thumbnail conversion. Daily caps still count attempts, including backfill. Failed or small-image operations retain their conservative reservation. This shared module does not decide whether a viewer may read an image. Feature-specific media routes and cleanup own that authorization and object lifecycle.

Storage reservations use an atomic D1 batch: conditionally increment a shared byte counter, insert the object ledger row only when that succeeds, and renew its durable cleanup lease. The initial application ceiling is 8,000,000,000 bytes; a member may reserve 250,000,000 bytes. Actual processed sizes count for new objects. Existing objects are conservatively charged 8 MiB each during migration. Reservations, stored objects, and deletion backlogs all count until R2 deletion succeeds; retries release bytes once. These are application storage limits, not a provider-wide billing cap or a limit on externally written objects.

## Private delivery

Post, avatar, and full event-cover routes call `privatePhoto` only after fresh authentication and feature authorization select the current immutable object key. The event preview endpoint also uses it, after independently authorizing the current event-link credential for the processed cover thumbnail; it grants no access to other private media. A named Workers Cache API cache holds processed bytes for one hour, shared across authorized viewers. It is separate from the default HTTP cache. Keys include the configured app origin and encoded object key, so each variant/replacement gets its own entry; URLs under `/media/_objects/` have no serving route and return 404. Never overwrite an object key with new bytes. Missing objects and denied requests are not cached.

Every member-media view still checks current session, membership, blocks, and the feature’s visibility/publication rules in D1. Event preview media instead rechecks its link credential, publication, active creator, and known-viewer blocks. Deletion, follower removal, logout, and avatar replacement take effect without a cache purge. Previously authorized in-flight responses can finish, just as with direct R2 delivery; downloaded content cannot be recalled. Revoked object bytes can remain internally until cache expiry/eviction, but no current authorized route selects them.

Cache opening/lookup has a 250 ms deadline and falls back to R2 on timeout or failure. Misses stream from R2 while a cloned, bounded image fills the cache through `waitUntil`; write failure does not fail the response. No cross-request promises are retained. Client responses are reconstructed with `private, no-store` and no internal cache metadata or cookies. Conditional/range headers never reach the internal cache, preserving the existing complete-response behavior. No browser or service-worker image cache is added.

The [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/) is local to the executing data center and may evict entries early. This saves R2 reads on hits, not authorization queries, Worker invocations, transformations, or client download bytes. Telemetry records lookup outcome/time and actual R2 reads without object keys. Real Workers-cache integration tests warm all variants, remove synthetic R2 objects to prove reuse, and verify revocation and replacement with entries still present. Hosted hit rates and latency remain operational measurements.
