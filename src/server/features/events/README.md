# Events

Members with a profile photo create events with one cover photo, a title, description, plain-text location (no maps or geotagging), a start time, an optional end time within 30 days, and the creator's IANA time zone. Guests answer Going, Maybe, or Can’t go. An event without an end time is over twelve hours after it starts; answers then close. Hosts can edit details, replace the cover photo or link, and cancel. Cancelled events stay readable with answers closed; there is no deletion apart from account deletion.

Creation is a draft until its cover photo is processed. The draft, its host row, and a ten-per-day creation allowance commit in one batch; retrying the same ID and details converges, while different details conflict. Cover uploads use an `Idempotency-Key`, the shared photo-processing allowance (two units for full size and a 480px thumbnail), and storage reservation, following the avatar replacement pattern: old keys enter cleanup and new keys leave it only when the event references them. Scheduled cleanup deletes unreferenced `events/` objects in small batches, marks drafts without a photo deleted after a day, and removes expired email claims.

## Access

Each event has one URL, `/#event/<token>`, and texting it is the only way to invite someone. The token is 48 random characters whose SHA-256 hash is indexed and whose ciphertext (Better Auth encryption with `AUTH_SECRET`) lets anyone who can see the event get the URL again; the event view returns it with its version so the page can share it and show it in the address bar. The token stays in URL fragments and request bodies, never in a server-visible URL. Signed out, `POST /api/event-link` reveals only whether a link works (event ID and whether it admits new people); signing in through it is handled by [membership](../../membership/README.md). Signed in, `POST /api/events/open` records an access row with the current link version and returns the event. Opening grants viewing—details, cover, and hosts—while that version is current. Answering (or hosting) adds the guest list, answer counts, activity, and messages, and survives replacement. Replacing the link (version ID plus compare-and-set, retry-safe) stops the old URL, pending sign-ins, and access from merely opening it. When the ciphertext is missing (after a restore quarantine) the view returns the version without a URL so hosts can replace it.

Every read and write rechecks, in SQL, that the event is published, its creator is active, the viewer is active, and neither has blocked the other. A block with any other guest or co-host hides that person from lists and the log. Inactive members disappear from lists. Covers load only with a session after the same checks. Hosts appear with their name and their normal private avatar.

## Answers, guests, and activity

Who may answer lives in [membership](../../membership/README.md) alongside link sign-in: hosts never answer, a new answer needs an opened current link, at most 500 people answer an event (bounding notification fan-out), and an unchanged answer keeps its timestamp. Guest lists page 30 people per answer, newest change first. The event’s activity log merges each guest’s current answer with messages, newest first, reading at most one page from each index before merging 20 items. Hosts and guests post plain-text messages up to 2,000 characters (100 a day per member), retry-safe by client UUID. Authors and hosts can remove ordinary messages. Changing the time or location records a `changed` entry listing what changed; cancelling records `cancelled`. Title and description edits are silent. A conditional update guards edits against concurrent changes to time, zone, or location.

Answers and messages feed [Activity](../notifications/README.md): hosts hear about each guest’s current answer, every message reaches the other hosts, and host messages, changes, and cancellation also reach everyone who answered. No email is sent for event activity; Web Push follows the member’s existing opt-in.

Members without a profile photo can use events, Activity, and push; everything else still requires a profile photo. Account deletion ends a creator’s events (photos to cleanup, ciphertext cleared) and removes the person’s hosting rows, access rows, answers, messages, and pending claims.

Integration tests in `tests/events.test.ts` and `tests/worker.test.ts` cover creation limits and retries, signed-out link checks, opening and recorded link versions, viewing versus participating, media for members, strangers, and anonymous requests, blocked, inactive, and replaced-link cases, answer rules, closing times, pagination, messages, notifications, joining through a link with a name-only profile, account deletion, photo processing, and migration 0030 preservation.
