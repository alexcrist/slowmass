# Profiles and relationships

Active verified members have a unique lowercase handle (the UI calls it a username), a profile name, and a private bio. New members send only a name: the server derives a handle from it, adding a random suffix when taken (the name itself need not be unique), and an update without a handle keeps the current one. Members can change their handle through the own-profile update. A single conditional write and the case-insensitive unique index arbitrate concurrent claims. Literal API route names are reserved. Renaming releases the previous handle immediately; no aliases or redirect history are retained. Posts, interactions, relationships, and invitation provenance use stable account IDs and remain attached to the same member. Profile setup is resumable: saving identity precedes the required avatar upload. Photo completion gates relationship mutations, connection lists, posts, and interactions; discovery and profile previews also allow active members without a photo. The own-profile endpoint, avatar upload, events, Activity, and push remain available without a photo. For unfinished viewers, profile reads return identity only, with a null bio and no follow state, even when a legacy automatic follow exists. Incomplete setup remains private until a photo exists: member profile lookup, discovery, and connection lists join the avatar record before pagination. Profile lookup reveals username, name, and the viewer's relationship state to active members. Bios, posts, and accepted Following/Followers lists require ownership or a current accepted follow. Blocked and inactive accounts are hidden.

Follow requests are directional and unique. Acceptance is owner-only. Cancel/deny affects pending requests; unfollow/removal revokes accepted access. Blocking atomically removes both directions and prevents subsequent requests. Unblocking restores no relationship. Requests are capped at 100 outstanding per member. Requests and blocked-account lists remain owner-scoped. Profile Following/Followers lists expose accepted relationships only to the owner and their accepted followers. All lists are sorted by current handle and bounded to 20 entries with explicit cursor pagination. The page query rechecks owner/viewer membership, the accepted follow, blocks, and profile completion; it excludes accounts blocked in either direction with the viewer before pagination. Removed follows revoke subsequent pages immediately.

For members who joined through a former personal invitation, initial profile creation establishes mutual accepted follows with the inviter once both profiles exist, through migration 0011's trigger; invite and event links create none. Active membership and blocks are checked atomically. Edits never restore removed follows; existing complete profiles are not retroactively connected.

Accepted relationships produce new-follower Activity and opt-in push through the [notifications](../notifications/README.md) source triggers. Invitation follows wait for both participants to finish photo setup before notifying them. Relationship changes and notification versions commit together; removal/blocking also removes the corresponding pending alerts.

Discovery returns pages of 20 active, unblocked members excluding the viewer. Persisted random keys and a random starting seed produce a stable shuffled ring across cursor pages. Literal ordered-subsequence matching searches usernames and names case-insensitively: partials and missing letters work, arbitrary misspellings do not. Search requires at least three characters; the server limits discovery to 30 requests/member/minute. Empty queries browse the directory. Input wildcards are escaped. Search predicates can scan profiles, so inspect rows read before expanding beyond small usage; the empty directory uses indexed key ranges without random sorting.

Profile reads evaluate authorization in the query. Avatar media requires membership and no blocks; post media additionally requires accepted access. A previously downloaded photo cannot be recalled. Avatars and relationship lists have no public access. Unauthorized profile-list reads return a safe error without disclosing accounts.

Only the own-profile setup response includes photo-completion state. Member-facing profile, discovery, post, and like responses no longer carry optional-avatar flags.

Renames can move an account between username-sorted relationship or liker pages during pagination. Discovery retains its stable random key. Existing links to the old username stop addressing the original member and can point to someone else if that name is claimed.

Discovery allowance and relationship target resolution belong to the public domain functions. Routers validate HTTP input, authenticate, and translate domain outcomes. In particular, block/unblock target resolution intentionally differs from ordinary profile visibility so blocking someone who already blocked you remains possible.
