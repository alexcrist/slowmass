# Posting and feed screens

The home feed merges the viewer’s own published posts with posts from accepted follows in newest-first order. Own posts use the same snapshot, cursor, and 12-post page limit. Eligible authors include the viewer directly; no self-follow is stored. Indexed candidate selection reads at most one page plus a sentinel per author before hydrating the final page. Drafts, failed uploads, and deleted posts remain absent; current membership, follow, and block checks still govern every other author. Profile queries remain restricted to that profile’s author.

The composer selects one still image, provides a local object-URL preview, and caption, then creates a draft and uploads the photo. Object URLs are revoked when replaced or unmounted. The optional photo-description input is omitted for now; new drafts send an empty description while existing stored descriptions remain in image alt text. A stable operation ID survives network retries. Cancellation requests draft deletion; uncertain cancellation is reported honestly. Successful publication navigates to the member's profile.

Feeds and profile posts use explicit Older/Newer controls and preserve cursor history. Reselecting Feed or your Profile starts a new snapshot; there is no persistent refresh button. Failed reads offer Retry. The first feed/detail photo loads eagerly with high fetch priority; subsequent feed photos are lazy. Profile grids use 480px thumbnails and eagerly load their first row. Image loading never requests another page. The owner’s three-dot header menu opens caption editing or a deletion confirmation dialog. Caption saves update in place; failed saves retain the draft. Images and chronological order cannot change. Private content is not persisted to local storage, cached by a service worker, or sent to third-party image hosts. All validation and visibility decisions remain server-authoritative.

Feed cards identify authors by username and avatar, linking to their profile. Profiles use a three-column square thumbnail grid. Both grid and feed photos link to a dedicated post route, also used by Activity. It shows the full-aspect-ratio photo and interactions with comments initially expanded, without the surrounding profile or list. The shell supplies a contextual back link above its heading, falling back to Feed for direct entry. Returning retains the list's pagination cursors and refetches its contents, reflecting deletions and current permissions. A deleted focused post leaves confirmation and the back control available. Loading and failed reads hide old results and end markers. Lists and photo details provide retry controls. The end marker is a short, centered gray horizontal line with an accessible label.

The shared card centers the avatar, username, relative timestamp, and owner menu vertically. Long usernames truncate instead of pushing the menu onto another row. Timestamp tooltips retain the full date. The menu supports outside dismissal, Escape, Tab, and arrow-key navigation. Both feed and dedicated post views use it.

Caption edits accept only a string up to 2,000 characters, including an empty caption. One conditional update requires the current active owner and a published post; it changes no media, publication timestamp, or interactions. Repeating the same save is idempotent; simultaneous different edits use the last successful write. Foreign-origin, non-owner, draft, inactive, and deleted-post edits fail.

Draft creation and its processing allowance now commit in one D1 batch. A failed draft insertion leaves no new reservation; an unconfirmed commit is safe to retry. Equal concurrent requests resolve to the same draft, different payloads conflict, and an owner losing a UUID collision retains no charge. A pending reservation left by the previous implementation can be resumed without another charge. Publication still claims the draft before transforming and keeps durable object cleanup intent around external R2 operations.
