# Interaction controls

Post cards receive counts and like state with the post response. Like mutations are idempotent and return authoritative counts directly. The client applies that response without a second detail request; failed mutations retain the prior counts and allow retry. Comment changes still refresh post counts. Comments load only when expanded; the dedicated post page expands them initially. They use explicit paging and permission-controlled deletion. The delete control is a trash icon with an accessible Delete comment name and a 44px touch target. It opens a confirmation naming the author before sending the deletion. Cancellation makes no request, pending deletion disables dismissal and resubmission, and a failure retains the dialog for retry. Success closes it and refreshes comments and counts; a failed count refresh reports that deletion succeeded instead of inviting another deletion. The composer pairs a one-row, multiline-capable textarea with a Post button in a horizontal row. Its label remains accessible to screen readers; whitespace-only and pending submissions are disabled. Failed submissions retain their text and UUID for unchanged retries; editing the text starts a new operation. Comments and likes distinguish pending reads from empty lists, clear old read errors on retry, and ignore late responses from earlier pages. Network errors remain visible with retry controls; private content is not persisted in browser storage.

Heart and comment controls use icons with accessible names and positive counts. The heart toggles the like; the adjacent count opens a native Liked by modal with explicit pagination and username/avatar profile links. List separators appear only between people, with no divider below the last row. Icon-to-count spacing is the same for likes and comments. Comment authors use username profile links. Profile names are kept on profile pages.

The post heart aligns with the content's left edge. Its reaction group offsets the button's extra leading space while retaining the 44px button and the 4px gap to a positive count.

Comments have a compact avatar/text layout with the username inline before the body, relative time and a clickable positive like total beneath it, and a heart on the right. Threads remain flat. Comment likes use idempotent mutations returning authoritative counts; failure preserves the prior state. Their likers use the same modal as post likes. Closing or leaving cancels pending list reads, and reopening loads fresh authorized data.
