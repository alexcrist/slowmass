# Interaction controls

Post cards receive counts and like state with the post response. Like mutations are idempotent and return authoritative counts directly. The client applies that response without a second detail request; failed mutations retain the prior counts and allow retry. Comment changes still refresh post counts. Comments load only when expanded; the dedicated post page expands them initially. They use explicit paging and permission-controlled deletion. The delete control is a trash icon with an accessible Delete comment name and a 44px touch target. It opens a confirmation naming the author before sending the deletion. Cancellation makes no request, pending deletion disables dismissal and resubmission, and a failure retains the dialog for retry. Success closes it, removes the deleted row immediately, and refreshes comments and counts while keeping other avatars mounted; a failed count refresh reports that deletion succeeded instead of inviting another deletion. Feed and detail posts use the shared `Composer` (see `src/client/ui/README.md`) with an accessible Post comment name and a 1000-character limit. The form has no outer margin; post-body padding matches the feed divider-to-next-header gap. Its label remains accessible to screen readers; whitespace-only and pending submissions are disabled. Failed submissions retain their text and UUID for unchanged retries; editing the text starts a new operation. Adding a comment revalidates the first page in place; posting from an older page requests the first page without rereading the old one. Comment rows retain stable identities when counts change. Refreshed post counts preserve expanded comments and unsent drafts. Comments and likes distinguish pending reads from empty lists, clear old read errors on retry, and ignore late responses from earlier pages. Network errors remain visible with retry controls; private content is not persisted in browser storage.

Heart and comment controls use icons with accessible names and positive counts. The heart toggles the like; the adjacent count opens a native Liked by modal with explicit pagination and username/avatar profile links. List separators appear only between people, with no divider below the last row. Icon-to-count spacing is the same for likes and comments. Comment authors use username profile links. Profile names are kept on profile pages.

The post action row is a compact, left-aligned flow shared by feed and focused posts. The heart aligns with the content's left edge; 24px icons never shrink, and 14px semibold counts sit 7.2px from their icon. The groups have a 19.2px gap; both values are shared CSS variables on the action row and grow with their contents rather than reserving fixed columns. The heart retains its 44px button; the separate like-count button has a compact minimum 24px width and 44px height. The comment control is left aligned within its 44px minimum target, so adding its own count never recenters its icon. Zero counts remain hidden. The comment group follows the like group's current width, including when the like count appears or disappears.

Comments have a compact avatar/text layout with the username inline before the body, relative time and a clickable positive like total beneath it, and a heart on the right. Threads remain flat. Comment likes use idempotent mutations returning authoritative counts; failure preserves the prior state. Their likers use the same modal as post likes. Closing or leaving cancels pending list reads, and reopening loads fresh authorized data.

Expanded comments use the post card's shared 16px vertical gap: from the action icons to the first comment, between comments, and from the final metadata line to the composer. Spacing subtracts the invisible padding inside touch targets: 10px below post icons and 16px below the metadata's 20px line box. Every metadata item, including a timestamp with no adjacent actions, occupies a 44px height, so adding a like count or delete control does not shift the timestamp or change a single-line metadata row's height. Metadata text and the delete icon sit 4px above the target center to bring the second line closer to the comment body, with matching timestamp/button alignment. The added space below the visible metadata supplies the shared gap, so rows need no extra bottom padding. Wrapped metadata retains the same item heights. Lists have no default margins; a populated comment-pagination row gets a separate 16px gap before the composer. Equal 16px horizontal gaps separate metadata items; the 14px trash icon sits at the leading edge of its retained 44px target and is lifted 2px to align optically with Source Sans 3 text.
