# Optional device setup

After a new member saves the required profile photo, one optional screen offers installation and notifications, using the same controls as Settings. Continue and main navigation remain usable during loading, permission dialogs, and failures; neither choice changes member eligibility. Continue or navigating away dismisses the account-level offer immediately and saves that choice independently. A failed save leaves the app usable with one retry action; reloading before the save succeeds can show setup again. Existing members are not enrolled by migration 0027.

Android offers installation and push independently. iPhone/iPad browser windows show Home Screen instructions and explain the push prerequisite; an installed window hides the entire installation section and offers notifications directly. A browser tab that just completed installation still shows the relevant launch guidance. Desktop omits installation. Existing browser permission and authenticated subscription are checked without prompting. A window with all available choices already resolved leaves setup automatically. Installation never requests notification permission. Unsupported browsers can continue.

Bootstrap supplies pending setup from the server. This survives isolated iOS storage, a reload, or a separate sign-in without persisting credentials or private content locally. Opening a new Home Screen app checks the existing cookie session before asking for login. Unfinished profile setup still runs first. Returning to a pending setup screen rechecks whether another window completed it, without polling. Once dismissed, the onboarding offer stays dismissed across devices; Settings always remains available for that device's own choices.

There is no cross-browser auth transfer or automatic app launch. Since iOS 17.2, installation can copy cookies into a new app, but pre-existing apps and other isolated browsers may still require sign-in through the existing email-link flow. [WebKit cookie-copying behavior](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/#login-cookies).

Node component tests cover profile gating, session reuse, resumption, skipping, navigation, and failed persistence. Provider/browser APIs are boundary fakes; these tests do not establish OS installation, permission UI, or delivery. Browser and visual testing are prohibited.
