# Events

The Events tab lists upcoming events (soonest first) and past events (most recent first) that the member hosts, answered, or opened through the current link (“You’re invited”), with explicit page controls. Members with a profile photo can create events from New event, at the right end of the Upcoming/Past tab row; the form reuses the post crop editor for a required cover photo, collects a title, date, start time, optional end time, location, and description, and uses the browser’s time zone. An end time earlier than the start ends the next day. Editing keeps the event’s time zone and notes that time or location changes notify guests. Stable event, message, and upload IDs make unchanged retries converge; any edit starts a new attempt.

`EventRoute` opens `#event/<link>` URLs through `/api/events/open` (explaining an unavailable link) and shows `#event/<id>` routes directly; the page then rewrites the address bar to the event’s one URL so copying it works. Event pages have no back control: Events is always in the sidebar or bottom bar, and in the header for members without a photo. They show the full-width cover photo, title, date and time in the event’s time zone with its abbreviation (`time.ts`), location, hosts, and description. Hosts and guests answer with three toggle buttons, each with an owner-chosen emoji (🪩 Going, 🎲 Maybe, 🫠 Can’t go, hidden from assistive technology); the choice gets a heavier border and gray fill. Until guests answer, a note explains that answering shows who’s going. Beside the title, a mail icon opens a dialog with the event URL, a Copy button, and “Send the link to your friends to invite them.”; when copying fails, the dialog says to select the link instead. Hosts also get an overflow menu with Edit event, Edit hosts, and Cancel event; cancelling asks for confirmation. Edit hosts lists hosts (the creator can’t be removed; other hosts can be removed or stop hosting, which returns them to Events) and pending emails, and adds a host by email. Adding replies the same whether or not the email has an account. A member whose email a host added sees a prompt on the event to become a host or decline. After answering, the guest list uses keyboard-navigable tabs per answer with counts, and the activity log combines answers and messages, newest first, with a message composer below it matching comments. Removing a message asks for confirmation. Guest lists and the log identify people by name only, since new members never choose a username. Guests without a profile photo show their initial, and only members with a profile page are linked—never for viewers in the events-only app.

Members without a profile photo see a reduced app: Events, Activity, and Settings (add a profile photo, edit name, installation, notifications, sign out, delete account) from the header, with no bottom bar or sidebar. Adding a photo switches to the full app. Signed-out visitors to an event URL see only the [sign-in screen](../welcome/README.md).
