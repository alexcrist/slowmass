# Events

The Events tab lists upcoming events (soonest first) and past events (most recent first) that the member hosts, answered, or opened through the current link (“You’re invited”), with explicit page controls. Members with a profile photo can create events from New event, at the right end of the Upcoming/Past tab row; the form reuses the post crop editor for a required cover photo, collects a title, date, start time, optional end time, location, and description, and uses the browser’s time zone. An end time earlier than the start ends the next day. Editing keeps the event’s time zone and notes that time or location changes notify guests. Stable event, message, and upload IDs make unchanged retries converge; any edit starts a new attempt.

`EventRoute` opens `#event/<link>` URLs through `/api/events/open` (explaining an unavailable link) and shows `#event/<id>` routes directly; the page then rewrites the address bar to the event’s one URL so copying it works. Event pages have no back control: Events is always in the sidebar or bottom bar. The cover is a keyboard-accessible button that opens the shared large-photo modal on phones and desktop, using the same authorized cover URL; closing or navigating away discards the modal. Pages show the full-width cover photo, title, date and time in the event’s time zone with its abbreviation (`time.ts`), location, hosts, and description. Hosts and guests answer with three toggle buttons, each with an owner-chosen emoji (🪩 Going, 🎲 Maybe, 🫠 Can’t go, hidden from assistive technology); the choice gets a heavier border and gray fill. Until guests answer, an explicit locked Guests section says “RSVP to see who’s going” and explains that any answer unlocks guests and activity; closed events explain that the list remains hidden and RSVPs are closed. Beside the title, only hosts (the creator and accepted co-hosts) see the mail icon that opens a dialog with the event URL, a Copy button, and “Send the link to your friends to invite them.”; when copying fails, the dialog says to select the link instead. The description has equal space between the title and copy row, accounting for the close button’s taller touch target. Hosts also get an overflow menu with Edit event, Edit hosts, and Cancel event; cancelling asks for confirmation. Edit hosts lists hosts (the creator can’t be removed; other hosts can be removed or stop hosting, which returns them to Events) and pending emails, and adds a host by email. Adding replies the same whether or not the email has an account. A member whose email a host added sees a prompt on the event to become a host or decline. After answering, the guest list uses keyboard-navigable tabs per answer with counts, and the activity log combines answers and messages, newest first, with a message composer below it matching comments and no extra top margin. Removing a message asks for confirmation. Guest lists and the log identify people by name only, since event joining only asks for a name. Guests without a profile photo show their initial and have no profile link. Host, guest-list, activity, and host-dialog avatars link to available profiles with accessible names and expanded pointer targets. Event-only viewers reach profile setup first; saving a photo continues to the selected profile. Host-dialog links are unavailable during a pending mutation. Guest names remain linked only for viewers with completed profiles.

Members without a profile photo use Events, Activity, and Settings within the full navigation; photo-only destinations have no lock badges and lead to explicit username selection followed by a profile photo. Signed-out visitors see `EventPreview`: a clear processed cover, title, and date followed by the [email form](../welcome/README.md). Its cover fetch keeps the credential in a POST body and revokes its in-memory blob URL on retry/unmount; failures leave the email form usable. No description, location, exact time, hosts, or guests enter the preview. Create/edit forms explain which fields anyone with the link can preview.

Cover uploads now distinguish saving details, byte transfer, and processing/saving, with measured transfer percentages and slow-phase messages. Details requests have a 30-second deadline; cover uploads have a two-minute deadline. Unmount aborts pending requests and suppresses late navigation; a synchronous request guard prevents duplicate submissions. Unchanged retries preserve IDs and photo bytes. Changing a new event's details rotates both its event ID and its cover-upload ID, so a prior cover acknowledgement cannot be mistaken for publication of the new draft. As before, editing after an uncertain result can start a separate event; retry unchanged details first or check Events.
