# Events

The Events tab lists upcoming events (soonest first) and past events (most recent first) that the member hosts, answered, or opened through the current link (“You’re invited”), with explicit page controls. Members with a profile photo can create events from New event, at the right end of the Upcoming/Past tab row; the form reuses the post crop editor for a required cover photo, collects a title, date, start time, optional end time, location, and description, and uses the browser’s time zone. An end time earlier than the start ends the next day. Editing keeps the event’s time zone and notes that time or location changes notify guests. Stable event, message, and upload IDs make unchanged retries converge; any edit starts a new attempt.

`EventRoute` opens `#event/<link>` URLs through `/api/events/open` (explaining a replaced link) and shows `#event/<id>` routes directly; the page then rewrites the address bar to the event’s one URL so copying it works. Event pages show the full-width cover photo, title, date and time in the event’s time zone with its abbreviation (`time.ts`), location, hosts, and description. Guests answer with three toggle buttons that mark the choice with a check as well as a border; until they answer, a note explains that answering shows who’s going. Everyone gets Share link (primary for hosts), which opens the system share sheet within the tap because the URL arrives with the event (Safari rejects it after a network wait); without a share sheet it copies, and clipboard failure shows the link in a read-only field. Hosts get Edit event, Replace link, and Cancel event in the overflow menu; replacing and cancelling ask for confirmation, and replacement works even when no URL is recoverable. After answering, the guest list uses keyboard-navigable tabs per answer with counts, and the activity log combines answers and messages with a message composer matching comments. Removing a message asks for confirmation. Guest lists and the log identify people by name only, since new members never choose a username. Guests without a profile photo show their initial, and only members with a profile page are linked—never for viewers in the events-only app.

Members without a profile photo see a reduced app: events, Activity, and Settings (add a profile photo, edit name, installation, notifications, sign out, delete account) from the header, with no bottom bar or sidebar. Adding a photo switches to the full app. Signed-out visitors to an event URL see only the [sign-in screen](../welcome/README.md).
