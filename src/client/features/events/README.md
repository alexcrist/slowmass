# Events

The Events tab lists upcoming events (soonest first) and past events (most recent first) that the member hosts, answered, or opened through the current link (“You’re invited”), with explicit page controls. Event rows use matching text size and line height with one consistent gap between the bold title, date, optional location, and answer. Members with a profile photo can create events from New event, at the right end of the Upcoming/Past tab row; the form reuses the post crop editor for a required cover photo, collects a title, date, start time, optional end time, location, and description, and uses the browser’s time zone. An end time earlier than the start ends the next day. Editing keeps the event’s time zone and shows no notification warning; detail edits are silent. Stable event, notification/message, and upload IDs make unchanged retries converge; changing a message starts a new attempt.

`EventRoute` opens `#event/<link>` URLs through `/api/events/open` (explaining an unavailable link) and shows `#event/<id>` routes directly; the page then rewrites the address bar to the event’s one URL so copying it works. Event pages have no back control: Events is always in the sidebar or bottom bar. The cover is a keyboard-accessible button that opens the shared large-photo modal on phones and desktop, using the same authorized cover URL; closing or navigating away discards the modal. Pages show the full-width cover photo, title, date and time in the event’s time zone with its abbreviation (`time.ts`), location, hosts, and description. Date, time, and location have decorative outline icons. The details use one consistent vertical gap through the answer buttons, and the Guests heading sits 4px above its tabs. Hosts and guests answer with three toggle buttons, each with an owner-chosen emoji (🪩 Going, 🎲 Maybe, 🫠 Can’t go, hidden from assistive technology); the choice gets a heavier border and gray fill. Until guests answer, an explicit locked Guests section says “RSVP to see who’s going” and explains that any answer unlocks guests and activity; closed events explain that the list remains hidden and RSVPs are closed. Beside the title, only hosts (the creator and accepted co-hosts) see the mail icon that opens a dialog with the event URL, a Copy button, and “Send the link to your friends to invite them.”; when copying fails, the dialog says to select the link instead. The description has equal space between the title and copy row, accounting for the close button’s taller touch target. Hosts also get an overflow menu with Edit event, Edit hosts, Send notification, and Cancel event; cancelling asks for confirmation. Edit hosts lists hosts (the creator can’t be removed; other hosts can be removed or stop hosting, which returns them to Events) and pending emails, and adds a host by email. Adding replies the same whether or not the email has an account. A member whose email a host added sees a prompt on the event to become a host or decline. After answering, the guest list uses keyboard-navigable tabs per answer with counts, and the activity log combines answers and messages, newest first, with a message composer below it matching comments and no extra top margin. Removing a message asks for confirmation. Guest lists and the log identify people by name only, since event joining only asks for a name. Guests without a profile photo show their initial and have no profile link. Host, guest-list, activity, and host-dialog avatars link to available profiles with accessible names and expanded pointer targets. Event-only viewers reach profile setup first; saving a photo continues to the selected profile. Host-dialog links are unavailable during a pending mutation. Guest names remain linked only for viewers with completed profiles.

Send notification opens the shared dialog with a required message and explains that everyone who RSVP’d and the other hosts receive Activity, only opted-in devices receive push alerts, and no email is sent. The native form has a 2,000-character limit, blocks duplicate submission and dismissal while sending, and preserves its text and ID after failure. Editing the text starts a new attempt. Success closes the dialog, announces confirmation, and refreshes the event log without discarding an ordinary message draft. Only hosts of an uncancelled event see the action; the server independently enforces access. Detail edits produce no log entries or notifications, including historical change entries.

Members without a profile photo use Events, Activity, and Settings within the full navigation; photo-only destinations have no lock badges and lead to explicit username selection followed by a profile photo. Signed-out visitors see `EventPreview`: a clear processed cover, title, and date followed by the [email form](../welcome/README.md). Its cover fetch keeps the credential in a POST body and revokes its in-memory blob URL on retry/unmount; failures leave the email form usable. No description, location, exact time, hosts, or guests enter the preview. Create/edit forms explain which fields anyone with the link can preview.

Cover uploads now distinguish saving details, byte transfer, and processing/saving, with measured transfer percentages and slow-phase messages. Details requests have a 30-second deadline; cover uploads have a two-minute deadline. Unmount aborts pending requests and suppresses late navigation; a synchronous request guard prevents duplicate submissions. Unchanged retries preserve IDs and photo bytes. Changing a new event's details rotates both its event ID and its cover-upload ID, so a prior cover acknowledgement cannot be mistaken for publication of the new draft. As before, editing after an uncertain result can start a separate event; retry unchanged details first or check Events.

## Appearance

Edit event offers separate Color theme and Fonts buttons. Each opens a native radio-group dialog with a live preview and explicit Save/Cancel. Font options render their own heading, body, and wordmark faces, so opening Fonts loads those local previews on demand; Color theme does not load the catalog. Cancel, Escape, and backdrop dismissal restore the last saved appearance. Saving disables dismissal and duplicate submissions, and a confirmed response updates the page immediately. Failures preserve the selection for retry; Reload appearance reads the latest authorized choices and updates the concurrency guard without losing unfinished event details. Unmount aborts pending saves/reads and ignores late replies. Appearance saves separately from the event-detail form.

The mounted event page, edit form, or credential-authorized signed-out preview owns document-root color and font variables, covering navigation/header portals, safe areas, native dialogs, body text, headings, the wordmark, and controls. A layout-effect cleanup restores previous values and the browser theme color on route changes, unavailable events, or unmount. New-event forms, event lists, profiles, Activity, and Settings use normal app styling. The default Original pairing keeps Source Sans 3 headings and the Caveat wordmark; other pairings use their display face for both headings and wordmark. Unsupported characters fall back to system fonts. No appearance or private event data is stored in browser storage.

[Shared identifiers](../../../shared/event-appearance/README.md) keep client/server choices aligned. The palette distinguishes the page canvas, input surface, structural dividers, stronger control outlines, and hover/disabled surfaces. These roles replace the normal gray boundaries throughout the shell, including navigation, forms, file controls, and upload progress. Crop handles stay high contrast against photo bytes. Local WOFF2 face declarations use swap and are requested only when used by the active pairing or visible font previews; no catalog preloads, third-party font requests, or new runtime dependencies are introduced. Font files have content-hashed names and immutable caching; licenses and source URLs live in `public/fonts/events/`. Contrast calculations, font-asset checks, component lifecycle tests, and Workers/D1 tests verify the contract without browser or visual testing.
