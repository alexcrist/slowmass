# Install support

slowmass is an online-only installable web app. The root document links a manifest with stable identity/scope, standalone display, and local 192px/512px icons. A separate opaque maskable icon keeps the monogram inside the safe region; iOS uses the existing apple-touch icon.

Installation support is mobile-only (iPhone, iPad, and Android). Device hints choose whether to show the Settings row, including iPadOS with a desktop user agent; viewport width and a touchscreen alone never classify a desktop as mobile. These hints do not prove installability: the native button still requires a browser-provided prompt. Desktop has no installation row, help, or in-app prompt; automatic prompt events are suppressed. The shared manifest remains necessary for mobile installation. A desktop browser can still offer its own website installation menu.

`InstallProvider` retains the browser's `beforeinstallprompt` event across member page changes. `InstallApp` appears as a matching expandable Settings row and offers a native install button when that capability is available. It consumes each prompt once, handles dismissal/failure, and replaces installation help with installed status after `appinstalled` or in standalone mode (including iOS's standalone flag). Manual instructions cover Safari on iPhone/iPad and Chrome on Android. Installation itself introduces no automatic prompts, analytics, polling, or offline storage. Its exported installation/device state also provides iPhone/iPad guidance to the separate push opt-in, which registers a push-only service worker after permission.

Email links can open a different browser/session from an installed app. The signed-out screen offers a manual unused-link paste flow, documented in the welcome feature. Device installation and session handoff are not browser-tested; the owner can confirm them on their actual phone. Verify manifest/icon metadata, type checking, unit/API tests, and deployment HTTP responses instead.

References: [MDN installability](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable), [install prompt event](https://developer.mozilla.org/en-US/docs/Web/API/BeforeInstallPromptEvent).

Standalone windows may omit browser navigation/reload controls. Content is read when entering a page; reselecting Feed, Activity, or your own Profile fetches the latest first page. Settings offers Reload app for a full reload, and secondary pages have labeled back navigation. Native pull-to-refresh is not required, and no custom pull gesture or automatic refresh is introduced. See [display modes](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/display).

Manual steps were checked against current vendor documentation on October 11, 2026. Safari on iPhone may place Share in the page menu; iPad exposes additional actions under View More/More. Android Chrome uses Install and create shortcut, with Add to Home screen wording on earlier versions. Opening an installed app may require a separate sign-in. Sources: [iPhone](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios), [iPad](https://support.apple.com/guide/ipad/open-as-web-app-ipad8f1f7a29/ipados), [Android Chrome](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=en).
