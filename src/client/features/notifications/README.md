# Notifications

A member opens this tab to load current in-app activity; no background polling occurs. All and Follow requests filters share the same screen; requests are accepted or denied in place. The request filter is applied by the server before pagination, and changing filters resets the cursor. There is no separate request-management page. Grouped likes and comments open an authenticated post detail. Read acknowledgement is explicit and limited to the displayed page. Navigation uses cursor history; reselecting Activity resets to current activity. No persistent refresh button is shown; failed reads have Retry. Photo detail has an arrow back control that returns to the current list/filter. All errors, loading, empty, and unread states are text-based.

Successful follow decisions and read acknowledgements switch the affected list to loading while refreshing, so old actionable requests and unread labels cannot linger as if nothing changed. Failed reads expose retry without suggesting an empty page.
