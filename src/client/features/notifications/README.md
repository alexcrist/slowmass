# Notifications

Requests, new followers, grouped likes, and comments share one newest-first timeline with explicit Newer/Older pagination. There are no filters or separate request section. Like/comment rows are native post links with private, lazily loaded 64px thumbnails on the left; the entire padded row is clickable and keyboard accessible. Targets reauthorize through the existing post/media APIs. Follow requests retain their independent profile link and Accept/Deny buttons. New-follower rows link to the current profile and use “started following you” without decision buttons. They share the same summary visibility tracking and badge as every other activity type. Reading a request does not accept, deny, or hide it. Acceptance replaces it with follower activity; removed sources disappear through normal authorized reads.

The member navigation shows one unread-item count, capped visually at 99+. A like group counts as one item. Completed members fetch it on mount, navigation, focus, reconnect, return to a visible tab, and every minute while visible. Read acknowledgements and successful request decisions refresh the count without reloading the list. Requests have a 15-second deadline; temporary count failures retain the last confirmed count. Unmounting aborts outstanding reads and stops polling. No private state is persisted locally.

Opening Activity only fetches its current page. IntersectionObserver tracks each unread item’s summary text, so a comment taller than the screen can still qualify. At least half the summary must stay on screen continuously for 250 ms. Exiting, hiding the tab, resizing, changing pages, or unmounting cancels incomplete timers; mobile navigation is excluded from the observable viewport. If the observer API is unavailable, nothing is automatically marked read. Qualified items are batched into versioned acknowledgements (up to the page size), and the badge changes after confirmed success. Failures show a status and retry with bounded exponential delay while this page remains mounted; hidden tabs pause retries. A late acknowledgement cannot clear a newer source version. No manual read button or per-type badge exists.

Navigation remembers pagination cursors; returning from a post refetches the same page, while reselecting Activity resets to the newest page. Successful follow decisions switch the list to loading so resolved requests cannot remain actionable. Failed reads expose Retry without implying an empty page. An optional push alert opens Activity at its matching event, including older pages, after current authorization. Missing targets fall back to current activity with a status message. Acknowledgement closes matching local OS alerts through that version. See [push](../push/README.md); email activity notifications and private offline caching remain absent.

Joined-invitee activity renders the whole row as a native profile link with a 64px private avatar and current handle. It uses the existing visibility dwell acknowledgement and unread badge. List/count requests opt into this event type, keeping older open clients compatible during rollout.
