# Posting and feed screens

The composer selects one still image, provides a local object-URL preview, caption and optional alt text, then creates a draft and uploads the photo. Object URLs are revoked when replaced or unmounted. A stable operation ID survives network retries. Cancellation requests draft deletion; uncertain cancellation is reported honestly. Successful publication navigates to the member's profile.

Feeds and profile posts use explicit Older/Newer controls and preserve cursor history. Reselecting Feed or your Profile starts a new snapshot; there is no persistent refresh button. Failed reads offer Retry. Photos load lazily without requesting another page. Deletion requires an inline confirmation. Private content is not persisted to local storage, cached by a service worker, or sent to third-party image hosts. All validation and visibility decisions remain server-authoritative.

Feed cards identify authors by username and avatar, linking to their profile. Profiles use a three-column square thumbnail grid; selecting a photo opens its full-aspect-ratio detail and interactions. Returning retains the current grid page; deletion reloads that page to remove the thumbnail and refresh pagination. Loading and failed reads hide old results and end markers. Lists and photo details provide retry controls. The end marker is an accessible check-circle icon, and photo details use the shared arrow back control.
