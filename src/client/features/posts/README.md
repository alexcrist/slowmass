# Posting and feed screens

Choosing a photo opens a freeform crop editor before publication. Drag any corner or edge to change aspect ratio, drag inside to move the crop, or use arrow keys (Shift for larger steps). The rectangle stays within the oriented photo with a minimum span of 10% per axis. Reset restores the full photo; Adjust crop reopens the original selection, avoiding repeated cropping of already encoded pixels. Cancelling keeps the previous confirmed crop and caption. No ratio presets or numeric input fields are used. Originals up to 32 MiB and 40 megapixels are accepted for local cropping. The selected crop is encoded locally at WebP quality 0.92 with a maximum 1600px long edge and an 8 MiB upload limit, then previewed through an object URL; the server still independently validates and re-encodes the upload. Confirming a changed crop starts a new draft ID; unchanged upload retries retain their ID and bytes. The original file stays only in memory. Object URLs are revoked when replaced or unmounted. The optional photo-description input is omitted for now; new drafts send an empty description while existing stored descriptions remain in image alt text. A stable operation ID survives network retries. Cancellation requests draft deletion; uncertain cancellation is reported honestly. Successful publication navigates to the member's profile.

The home feed includes your own published posts alongside accepted follows in newest-first order. Feeds and profile posts use explicit Older/Newer controls and preserve cursor history. Reselecting Feed or your Profile starts a new snapshot; there is no persistent refresh button. Failed reads offer Retry. The first feed/detail photo loads eagerly with high fetch priority; subsequent feed photos are lazy. Profile grids use 480px thumbnails and eagerly load their first row. Image loading never requests another page. The owner’s three-dot header menu opens caption editing or a deletion confirmation dialog. Caption saves update in place; failed saves retain the draft. Feed deletion removes only the confirmed deleted card before revalidating the current page, preserving other photos, expanded comments, and drafts. Fresh counts and captions update surviving cards without remounting them. Revalidation failure clears the page and offers Retry; pagination still loads a fresh authorized page. Images and chronological order cannot change. Private content is not persisted to local storage, cached by a service worker, or sent to third-party image hosts. All validation and visibility decisions remain server-authoritative.

Feed cards identify authors by username and avatar, linking to their profile. Profiles use a three-column square thumbnail grid. Both grid and feed photos link to a dedicated post route, also used by Activity. It shows the full-aspect-ratio photo and interactions with comments initially expanded, without the surrounding profile or list. Feed, focused-post, and upload-preview images fill their container width at natural proportions, up to a height of twice the container width. Taller images scale down within that limit without cropping. The limit follows container width rather than viewport height, so ordinary portraits stay full width. The shell supplies a contextual back link above the post, falling back to Feed for direct entry. Returning retains the list's pagination cursors and refetches its contents, reflecting deletions and current permissions. A deleted focused post leaves confirmation and the back control available. Loading and failed reads hide old results and end markers. Lists and photo details provide retry controls. The end marker is a short, centered gray horizontal line with an accessible label.

The shared card centers the avatar, username, relative timestamp, and owner menu vertically, with a consistent text size and line height. Long usernames truncate instead of pushing the menu onto another row. Timestamp tooltips retain the full date. The menu supports outside dismissal, Escape, Tab, and arrow-key navigation. Both feed and dedicated post views use it. The bottom card separator appears in the feed only; dedicated posts have no trailing divider.

Cards use one 16px vertical gap from the header avatar to the photo, from the photo to the action icons, and from the icons to the caption line box. The caption is passed into the interactions section so it renders after the action row: a bold @username profile link followed by the caption in comment type, then a 24px gap before expanded comments. Spacing accounts for the avatar and icons inside their larger touch targets; captions have no default paragraph margins. Mobile and desktop share these rules.

On the focused post page at desktop widths (900px and above), the photo itself opens the shared image viewer when tapped, clicked, or keyboard-activated. No separate visible enlarge control is added. This matches the breakpoint where the post narrows to 520px instead of filling the screen. Below it, the photo remains a plain image with no extra tab stop or click action. Resizing below the breakpoint closes an open viewer; returning to a wider screen does not reopen it. Feed photos continue to navigate to the focused post.

The viewer uses the same authorized full-size media URL, original aspect ratio, and alt text. It fits the image within the viewport over the same dark backdrop as profile photos, with loading/error/retry states and native dialog dismissal/focus handling. Opening it does not fetch post metadata or expose an original upload. Closing or navigating away discards viewer state; the shared image viewer adds no persistent cache.

A profile grid can begin its authorized API read while profile metadata is pending, but renders no content or image URLs until the parent confirms profile access. Resolving that parent does not refetch the page; existing pagination and cancellation rules apply.

The composer reports starting, uploading (actual byte progress), and processing/saving separately, with a slow-phase message. Creation and cancellation have 30-second deadlines; photo transfer plus response has a two-minute deadline. A submitted photo and caption stay fixed for retries until cancellation is confirmed; cancellation remains available after an upload error. Unconfirmed cancellation retains the operation ID, and cannot silently create a second post. A missing draft counts as cancelled. Local decoding and crop preparation each have a 30-second deadline. Server-confirmed processing failures require cancelling the old attempt before a new upload.

The composer lives separately from feed/detail rendering and loads on demand through the feature entry point, so browsing does not download its publication UI. Photo sizes, upload behavior, and authorization are unchanged.
