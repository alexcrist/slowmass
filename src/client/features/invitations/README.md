# Invitations

Send an email-bound invitation from Settings or the shortcut beside the profile Settings icon. A successful response confirms the email was accepted for sending; there is no copyable-message step. The email names the inviter, describes slowmass as a Seattle-based app for sharing photos with friends, and supplies a personal seven-day link to join without another email. It explains mutual follows and that the link must not be forwarded. The inviter cannot retrieve the recipient's join credential from the API or history.

History has explicit pagination, separate status/date/action rows, and wrapping space between the timestamp and Cancel invitation. It distinguishes joined, cancelled, expired, sent, unconfirmed delivery, and older invitations never emailed. Unsent invitations offer Send email or Retry email; existing invitations are never emailed automatically on page load. Only unused invitations can be cancelled. Cancellation retains issuance and delivery timestamps for incident review.

Creation failures reload history because the invitation may have been saved before email delivery failed. Successful sending or cancellation also reloads it with a loading state. Errors retain the entered address and give retry instructions; read failures have their own Retry control. There is no daily invitation limit per member. Server eligibility and shared email-delivery budgets remain authoritative.

One current invite link appears before the personal email form. Copy invite link reuses a valid credential and creates a new seven-day credential when absent or expired; copying does not extend expiry. The panel shows the expiry in the viewer’s locale and a selectable URL after copying. Clipboard failure gives manual-copy instructions. Link options uses the shared three-dot overflow menu; Replace link opens a confirmation explaining invalidation of the previous link and its outstanding verification emails. The dialog retains the selected version and operation ID through failed/ambiguous requests, disables dismissal/submission while pending, and reloads current metadata after errors. Copy retries also retain their operation ID. Shared links have no sign-up cap, history, or per-link joiner panels. Joined-invitee Activity continues to show completed profiles. Loading/read-error/retry states precede actions, and page loads create no credential. Node component tests cover ordering, copying/fallback, expiry, hidden replacement, cancellation, pending controls, and retry identity. Deployed with migration 0025; release verification is recorded in setup.md.
