# Shared interface controls

`Dialog` uses the native modal dialog for focus containment and an inert background, locks document scrolling, and restores the connected opener on close. Escape, the labeled Close button, and clicking the backdrop dismiss it unless a mutation is pending. Backdrop dismissal requires a press and release outside the dialog bounds: clicks in its padding and drags that begin inside it do not dismiss. Route unmounts close it and discard its contents. The image appearance removes the panel frame, hides the visible heading while retaining its accessible name, and places its close button at the viewport’s top right. It retains the same backdrop, Escape, and focus behavior. Avatar/post cropping, enlarged profile and event photos, relationship confirmations, post editing/deletion, and post/comment likers use the same primitive; no third-party UI dependency or private-content cache is added.

Crop dialogs use `announceWhileBusy` so pending mutations still block dismissal without marking the live progress messages as a busy subtree. Controls remain disabled; phase changes can be announced immediately. Component tests check these attributes, not actual assistive-technology delivery.

`RelativeTime` displays `now`, then whole minutes, hours, days, weeks, and 365-day years. Posts and comments keep an ISO datetime plus the full local date as the title and accessible name. A local minute timer refreshes the text and is cleared on unmount; it never requests server data.

`ImageViewer` composes the image dialog for profile photos, event covers, and focused post photos. Callers supply an authorized media URL, dimensions, alt text, and title. It preserves aspect ratio within the viewport, hides incomplete images behind loading/error status, and allows retry. It mounts only when opened and is discarded on close or route changes; profile, event, and post features own their respective open/availability rules.

`OverflowMenu` owns the shared vertical three-dot trigger, keyboard navigation, outside dismissal, and focus restoration. Post owners supply Edit caption/Delete post actions; other profiles supply Unfollow for accepted follows and Block account. Event hosts put Edit event, Invite people, Send update blast, and Cancel event in this menu; creators also get Delete event. Host management opens from Edit event. Selecting an action restores trigger focus before opening a dialog.

An open menu closes on outside pointer/focus events, page or enclosing-panel scrolling, window/visual-viewport changes, and hash navigation. Internal menu scrolling stays usable. Scroll/resize dismissal restores focus only when it was still inside the menu, using `preventScroll`; outside dismissal leaves the destination focus alone. Disabling the control or changing its action labels/order/danger state closes it immediately, without reopening on reenable. Equivalent rerenders retain the menu and use current callbacks.

On opening, measured placement prefers below the trigger, flips above when needed, and keeps an 8px viewport inset. Mobile placement also excludes the measured bottom navigation, including its safe-area padding; desktop sidebar geometry is not treated as a bottom obstruction. The colocated placement helper constrains height to the roomier side and width to the viewport. Tall menus scroll internally, including when keyboard focus moves to an offscreen item. Component and geometry tests use synthetic DOM measurements; they do not prove browser layout or assistive-technology behavior.

`ConfirmDialog` composes `Dialog` with shared Cancel/confirm actions, pending controls, and an inline failure message. Connections, profile unfollow/block actions, and comment deletion keep their selected target and mutation logic in the owning feature. Confirmation is a client safeguard; server authorization remains authoritative.

`CopyLink` shows a link in a read-only field with a Copy button and a status message; when the clipboard is unavailable, focusing the field selects it for manual copying. `MailIcon` is the envelope that opens a link dialog. The event link and invite link dialogs both use them; each feature owns how its link is fetched.

`Composer` is the text box for post comments and event messages, so both keep the same look. The signed-in member’s 32px avatar sits in the comment avatar column, or their initial before they add a profile photo; `ViewerProvider` (supplied by the member shell) provides it, and without a provider the field spans the full width. The field starts where comment text starts and ends at the like-button edge. It has the neutral hover fill with the photos’ 3px corner radius, turning to the surface color with a darker single outline on focus. Type is 16px with a 12px left inset. An aria-hidden copy of the draft sizes the textarea from one line (44px), so it grows with every wrapped line and newline and never scrolls internally; padding stays the same at any height, and clearing a sent draft shrinks it again. A Post text button sits inside the field at the bottom right with a 44px target: Douglas Fir when a draft can be sent, muted while it is empty, whitespace-only, pending, or blocked by a caller-supplied condition. Callers own the draft, the operation ID, submission, and error display.

`SettingsRowIcon` draws the decorative line icon that leads each Settings row, matching the navigation icons; its invite icon is MailIcon's envelope.

`LockIcon` marks the RSVP-gated guest list. It is decorative; adjacent text explains the restriction. Navigation destinations have no lock badges.

`ScreenBoundary` contains member-screen suspension and load/render failures while keeping navigation available. Loading is announced; failure offers an explicit reload with a warning about unsaved changes. It never reloads automatically. Route remounts reset the boundary, but failed module imports can require a fresh document.
