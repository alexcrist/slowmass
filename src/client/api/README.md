# API client

Same-origin fetch wrapper for JSON responses and safe server error messages. Session cookies are managed by the browser. Request cancellation is passed through standard fetch options; this module stores no credentials or private response cache.

Ordinary concurrent GETs to the exact same URL share a single in-flight read, including JSON decoding. Each caller can cancel independently; the transport aborts when its last caller leaves. Completed responses and failures are immediately discarded, and even a transport that ignores cancellation is bounded to fifteen seconds. Requests with custom headers or other fetch settings remain independent. Mutations are never shared or retried. Starting or completing a mutation separates subsequent reads from older work, including reads begun before its commit. Session listener changes similarly prevent sharing work across accounts. Components still own stale-response suppression and explicit post-mutation refreshes; this is request coalescing, not a data cache.

`useApiResource` manages component-scoped GET requests for lists and detail screens. Initial reads, URL changes, and retries expose loading with no old result or read error. Each request has a distinct identity, so returning to a previous URL still starts a fresh read; cancellation and identity checks prevent late responses from replacing the current screen. Consumers show empty states only after a successful result. Mutations remain feature-owned. After a confirmed mutation, `refresh` can retain the current same-URL result and apply a confirmed local change while rereading authoritative data, preserving unaffected mounted images. Controls use the loading flag to prevent stale actions during that read. Successful deletions are removed immediately. A failed or timed-out refresh clears the result; navigation, retries, and explicit reloads still hide old data. Overlapping refreshes abort obsolete reads. This adds no cache, persistence, polling, or automatic retries.

HTTP failures preserve their status in `ApiError`. A mounted session subscribes to unauthorized responses before its screens start requests. The first non-aborted 401 notifies that session once; subscription identity prevents late responses from an old session from invalidating a new sign-in. Server failures such as 503 remain ordinary retryable errors. The API module owns this transport signal; Welcome owns the sign-in transition. No private drafts or credentials are persisted during recovery.

List/detail GET reads have a fifteen-second deadline including response-body decoding. Expiry aborts the request and exposes the consumer's Retry action; late responses cannot replace the current result. Unmount/navigation clears the timer and aborts the old read. This does not replay mutations or clear a valid session.

`withDeadline` bounds browser/API operations for push, including transports that ignore cancellation. It removes its timer and optional abort listener on completion; callers own fetch abortion. Permission dialogs are deliberately outside this deadline.

Photo PUTs opt into `onUploadProgress`, using same-origin XMLHttpRequest for real request-body progress while retaining API error and session-expiry handling. Only its successful upload-body event moves the UI to processing; neither that event nor a percentage confirms publication. The complete request has a two-minute deadline, aborts on expiry/unmount, removes handlers/timers, ignores late callbacks, and requires an explicit success acknowledgement. Unknown byte totals omit the percentage. Timeout and connection errors explain that the result is unconfirmed and that retrying the same operation checks for completion. Requests are never automatically replayed. The transport follows the browser [upload event contract](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/upload).

Upload-related JSON creation, saving and cancellation requests opt into a 30-second deadline, including body decoding. Expiry aborts the transport without marking the caller's lifecycle signal cancelled, allowing the form to display the error and release its controls. `withDeadline` also accepts a duration/message for local image preparation; its existing push default is unchanged.

A component may initialize `useApiResource` with a freshly authorized response from the operation that opened it. Only that mount's initial GET is skipped; refresh, retry, and path changes perform normal reads. The response is component state, with no shared or persistent data cache. Event-link admission uses this to avoid immediately refetching the same event.
